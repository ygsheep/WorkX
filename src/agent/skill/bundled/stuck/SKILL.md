# Stuck — 停滞与卡死诊断

当你在原地打转时，**停止重试**，先做个一次性诊断，再决定出路。

## 1. 识别停滞
出现以下任一迹象即视为停滞（不要继续无脑重试）：
- 同一命令/同一方案反复执行且结果不变
- 连续多轮没有新增信息或实质进展
- 错误信息完全相同，说明根本没换变量

## 2. 一次性诊断（停滞审查）
停下来，审视并回答以下问题，形成判断：
- **目标**：最终要交付什么？当前离它还有多远？
- **障碍**：卡住的具体拦路点是什么？（失败的命令/缺失的依赖/权限/环境）
- **尝试过**：已尝试哪些方案？分别是为何失败？
- **假设**：你现在默认"一定成立"但其实可能错了的前提是什么？

## 3. 选一条出路
基于诊断，从最便宜的方案开始：
1. **换方向**：换一个完全不同但更简单的达成路径
2. **缩小**：把死磕的大目标切成可独立验证的小步
3. **求助**：明确说出需要什么外部输入（用户提供的信息/环境/权限/人）
4. **报错与收尾**：如实报告停滞原因、范围与建议，把选择权交还用户

禁止反复执行"再试一次上次失败的命令"。若判断重试仍然合理，必须给出和上次**不同的理由或变化点**。

## 4. 报告
给出：卡在哪 → 已尝试哪些（含失败原因）→ 判断的出路 → 需要用户决定什么。
简洁、如实，不粉饰"好像快好了"。
