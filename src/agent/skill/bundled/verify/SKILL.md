# Verify — 变更验证

**"看起来对了"不算完成。** 用可重复执行的证据核对成果，再决定是否收尾。

## 1. 明确验收标准
先写下对这个改动"通过"意味着什么——可被命令/检查判定为真/假的标准，例如：
- 构建成功（命令）
- 相关测试通过（`ctest` / 指定用例）
- 命令退出码 / 输出内容符合预期
- 静态检查无新增告警

## 2. 执行并留证据
- 实际运行验证命令，**记录输出/退出码**，不要用"按道理应该通过"代替
- 对照第 1 步标准逐条打勾；未覆盖到的标准要说明为什么跳过

## 3. 判定
- **全部通过** → 可声明"完成"，给出依据（运行的命令 + 其结果）
- **有失败** → 不宣称完成；回到修复，修复后重新验证
- **无法验证**（缺环境/缺权限/无判定手段）→ 明确说出"哪些未被验证、为何"，不要给出超出证据的完成声明

## 4. 收尾
报告里写明：验证命令、实际结果、与验收标准的对照。证据优先，再有结论。
