# Loop — 循环执行

有纪律的迭代循环。每轮都执行并检查，直到完成条件满足或明确放弃。

## 流程

### 1. 定义完成条件
开工前先写下**可验证**的完成标准（失败/成功均可判定的布尔条件），例如：
- 单元测试通过：`ctest -R xxx`
- 某命令退出码为 0
- 输出文件内容匹配期望

没有可判定条件就不要进入循环——那只是无休止的重复。

### 2. 单轮执行
- 执行一轮（运行工具/命令/修改）
- 记录本轮结果（关键输出、错误、耗时）
- 用完成条件做**通过/未通过**判定

### 3. 判定
- **通过** → 收尾，报告"完成 + 用了 N 轮 + 最后的判定依据"
- **未通过** → 检查是否达到迭代上限、是否陷入相同失败，然后进入下一轮

### 4. 停止条件
- 完成条件通过
- 达到迭代上限（与用户约定，或报告后询问）
- 连续多轮未见进展 → 报告"停滞"，列出尝试过的方案，询问是否继续
- 用户取消

## 纪律
- 每轮只做**一个**变更，判定后再决定下一轮动作。
- 不要为了"有进展"而做无关改动；没有进展也比错误改动好。
- 报告时给出**本轮做什么 → 观察到什么 → 判定**，而非笼统"在尝试"。

## 完成
回报：是否达成完成条件、总轮数、最后一轮的判定证据。
