### 2.2 关键架构约束（内存/工程约定）

- `ChatSession::run_completion` 每轮 **新建** ReActLoop（`chat_session.cpp#L882`），注入 provider/registry/config_manager 等；ReActLoop 构造参数已达 11 个，新增 Agent 类型**不得复制这套冗长注入**。
- ReActResult / ReActStep 承载步骤历史、token 统计、compactor 状态；新 Agent 类型**必须复用**这套结果载体，避免 UI 侧另起一套解析。
- 权限三态、压缩器（compactor）、环境感知均已注入 ReActLoop；Agent 编排层必须**透传**而非重建。
- `IReActObserver` 是事件发布解耦点，各 Agent 类型通过它发布步骤事件，UI 无需感知 Agent 类型差异。

## 3. 总体设计

### 3.1 架构分层

```
ChatSession::run_completion
      │  每轮调用
      ▼
┌─────────────────────────────────────────────┐
│ QueryEngine（编排器，唯一入口）                 │
│  · 解析 agent.active → AgentType             │
│  · 构造对应 Agent Loop（注入同一套依赖）        │
│  · QueryTracker 记录调用链（类型/目标/verdict）│
└─────────────────────────────────────────────┘
      ▼ 委托
┌─────────────────────────────────────────────┐
│  IAgentLoop（统一接口）                        │
│  ├─ ReActLoop          （默认，现状不变）       │
│  ├─ GoalGuardedAgent   (#31，目标驱动，包装/变体)│
│  └─ BatchAgent …       (#32，多模式扩展点)     │
└─────────────────────────────────────────────┘
      ▼ 复用
  IReActObserver → ReActEventPublisher → EventBus → TUI
```

**原则**：
1. **QueryEngine 是唯一编排入口**，接管 ChatSession 中"建 loop + 组装消息 + 事件发布 + shape 捕获"的职责，ChatSession 变薄。
2. **IAgentLoop 统一接口**：新 Agent 类型复用 `run()` 签名与 `ReActResult`，避免重复造轮子。
3. **agent.active 语义升级**：从"skill 过滤字符串"升级为"AgentType 路由 + 仍保留 skill 过滤"。
4. **渐进式落地**：#31 P0 先行（回报最高），#33/#32 做抽象但不全量实现（架构上可扩展即可）。

## 4. Issue 实现方案

### 4.1 #31 目标导向 Agent（P0，先行）

#### 4.1.1 目标定义（VERDICT 类型）

新增 `src/agent/core/goal_verdict.h`：

```cpp
struct AgentGoal {
    enum Type { TestsPass, BuildClean, LintZero, FileExists, CustomScript, None } type;
    std::string path;      ///< FileExists
    std::string command;   ///< CustomScript 命令字符串（经 shell_exec，走任务取消）
    int max_attempts = 50; ///< 最大尝试次数（可配置）
};
```

#### 4.1.2 验证器表（Verdict Checker）

新增 `src/agent/core/verdict.h`：

```cpp
// 返回 Verdicate：达成 / 未达成+进度说明 / 失败(兜底退出)
enum class Verdict { Achieved, Pending, Failed };
using VerdictFn = std::function<Verdict(const std::string& observe, std::string& detail)>;
```

内置验证器（注册表可按需扩展，同 WebSearch provider 模式）：
| Type | 实现 | 判定 |
|------|------|------|
| TestsPass | 运行测试命令，解析退出码/输出 | 全绿 |
| BuildClean | 编译命令，解析 warning/error 计数 | 零 error（warning 降级可配） |
| LintZero | lint 命令 | 零告警 |
| FileExists | 文件系统 stat | 文件存在 |
| CustomScript | 执行脚本，看退出码 | exit 0 |

#### 4.1.3 GoalGuardedAgent 循环（核心算法）

新增 `src/agent/core/goal_guarded_agent.{h,cpp}`，**内部持有 ReActLoop 复用其 Thought/Action/Observation/工具执行/压缩器/权限**，在外层包"目标验证环"：

```
1. 解析 AgentGoal（用户消息末尾/配置注入）
2. loop:
   a. verdict = Verify()          ← 先验（对 tests_pass 等"初始即达成"场景秒退）
   b. if verdict == Achieved → 成功退出（FinalAnswer 里附验证证据）
   c. if attempt > max_attempts → 失败退出（汇报当前状态，不截断为"已完成"）
   d. 复用 ReActLoop 跑 **一轮**（iteration==1 的压缩、单步 Thought+Action+Observe）
   e. attempt++
3. 返回带 goal 状态的 AgentResult
```

**关键差异点（对照 issue #31 表格）**：
- 终止条件：由 `tool_uses.empty()` → **verdict == Achieved**
- 失败处理：自动重试，直至达成或 max_attempts（默认 50，可配置）
- 单轮而非整体循环：需要"观察→验证→再观察"交错，故外层 while 每轮调一次单步 ReAct
- 用户干预：保留 `m_should_cancel` 协作取消；新增可配置"每 N 次未达成弹 AskUser 问是否继续"

#### 4.1.4 与现有代码的关系

- `ReActLoop::run()` 整体循环不满足"每轮验参"，需新增内部方法 `run_single_iteration()`（把现有 for 循环体抽成可供单步调用的私有方法），或提供 `MaxIterations=1` + 手动续调——推荐前者更清晰。
- **注意**：未达成时不能简单走 `run()` 返回 FinalAnswer 就退出，因为 ReActLoop 终止条件是"无 tool_use"，LLM 可能"自欺"提前 FinalAnswer。因此 GoalGuarded 必须忽略 LLM 的"自认为完成"的 FinalAnswer，强制跑 Verdict 后决定是否续一个受保护轮。
- 复用：`ReActResult`、`IReActObserver`、`ReActEventPublisher`、compactor、权限注入方式——全部透传给内部 ReActLoop。

### 4.2 #33 Agent 类型体系（P1，已实现：Planner/Executor/Coordinator/Researcher/Reviewer）

#### 4.2.x 角色 Agent 落地（RoleAgent，已实现）

五个角色本质是"带角色指令 + 工具集约束"的 ReActLoop 变体，因此用**一个
`RoleAgent` + `RoleProfile` 参数化**实现（`src/agent/core/role_agent.{h,cpp}`），
避免五个近似重复类：

| 角色 | agent.active | 提示覆盖（追加到 system_prompt） | 工具策略 |
|------|--------------|-------------------------------|----------|
| Planner | `planner`/`plan` | 只做只读规划，输出分步方案后等待确认 | 只读（is_read_only） |
| Executor | `executor`/`execute` | 严格按既定方案执行，不扩范围 | 全量 |
| Coordinator | `coordinator`/`coordinate` | 分解任务 + Agent 工具并行调度子 Agent + 聚合 | 全量 + 放行 AgentTool |
| Researcher | `researcher`/`research` | 收集→结构对比→报告 + 推荐 | 只读 |
| Reviewer | `reviewer`/`review` | 只读审查，severity 分级问题清单 + 结论 | 只读 |

- 只读角色 Filtered_schema：`is_read_only()` 过滤写/执行工具，从工具暴露面
  杜绝副作用（与 Plan 权限模式同思想，形成双保险）。
- Coordinator `keep_agent_tool=true` 放行 AgentTool（`kAgentToolName` 已在
  `agent_tool.h` 导出为公开常量供复用）。
- 接线：`query_engine::make_loop` 五分支 → `RoleLoopAdapter` →
  `ReActLoopFactory::make(deps, registry, cfg)`（新增通用构造，统一注入权限/
  事件/压缩器，`make_one_step` 改由其委托）。

实现文件：`role_agent.{h,cpp}`、`agent_loop_adapters`（RoleLoopAdapter）、
`query_engine::make_loop`、`agent_type.cpp`（`is_implemented` 五角色置 true）、
`goal_guarded_agent.{h,cpp}`（`ReActLoopFactory::make` 通用化）、`agent_tool.h`
（导出 `kAgentToolName`）。

**扩展点**：新角色只需新增一条 `RoleProfile` + `make_loop` 分支，无需改引擎。

#### 4.2.1 IAgentLoop 统一接口

新增 `src/agent/core/i_agent_loop.h`：

```cpp
struct AgentRunConfig {
    std::vector<ChatMessage>* messages;   ///< 会话历史（读写）
    std::string system_prompt;
    nlohmann::json tools_schema;
    std::atomic<bool>* should_cancel;
    AgentGoal goal;                        ///< 空 = 无目标守卫
    IReActObserver* observer;
};
struct AgentResult {
    ReActResult react;                     ///< 复用既有结果载体
    AgentType agent_type;                  ///< 记录本次类型
    GoalStatus goal_status;                ///< 目标验证状态（仅 GoalGuarded）
};
virtual AgentResult run(AgentRunConfig cfg) = 0;
```

- `ReActLoop` 实现 `IAgentLoop`（包装现有 `run()`），保证默认路径零改动。
- `GoalGuardedAgent` 实现 `IAgentLoop`（内部持有 ReActLoop 做单步驱动）。
- Planner/Coordinator/Researcher/Reviewer 本期**只做枚举与路由占位**，返回 `AgentResult{agent_type=Planner}` + 提示"未实现"；架构上允许后续填充，避免一次性铺开过重。

#### 4.2.2 QueryEngine 落地（替换空 stub）

`src/agent/core/query_engine.h` 从注释 stub 变为实体类：

```cpp
class QueryEngine {
public:
    QueryEngine(IConfigManager& cfg, ICompletionProvider* provider,
                std::shared_ptr<tool::ToolRegistry> registry,
                ITaskManager* tm, std::string cwd,
                CacheAwareCompactor* compactor, IEventBus* bus,
                skill::TouchCollector* touch, FileIndexInvalidator inv,
                std::string session_id);

    /// 一轮查询：解析 AgentType → 构造 Agent → 注入权限/事件 → run
    AgentResult run(QueryContext& ctx);

    /// agent.active 解析：String → AgentType（含 skill 过滤兼容）
    AgentType resolve_agent_type() const;
private:
    std::unique_ptr<IAgentLoop> make_loop(AgentType t, ...);
};
```

- 依赖注入沿用 ReActLoop 那套 11 参，但**收拢进 QueryEngine 一次性配置**，此后各 Agent 构造签名极简。
- ChatSession `run_completion` 中"创建 ReActLoop + apply_permission_state + set_permission_state_changed_callback + ReActEventPublisher + shape 捕获"整段**抽到 QueryEngine.run()** 内，ChatSession 只保留消息持久化与结果回填。

#### 4.2.3 agent.active 作为模式路由

- 原 skill 过滤逻辑（`chat_session.cpp#L810-817`）**保留**：agent.active 非空时仍只激活匹配 skill（兼容旧行为）。
- 新增用途：`QueryEngine::resolve_agent_type()` 将其解析为 AgentType；用户在命令面板切换时写入同一 key，即实现"模式切换"。
- 预留 `explore→ReAct`、`verify→GoalGuarded` 别名映射，满足里程碑"可切换 explore/verify 角色"目标。

### 4.3 #32 多模式扩展（P1，已实现：Script/Batch/Watch）

本期**落地三个多模式 Agent**（对应 `agent.active` 路由，均无需 LLM、复用
`ReActResult` 载体与 `guard_command` 白名单）：

| 模式 | agent.active | 目标语法 (agent.goal) | 行为 |
|------|--------------|------------------------|------|
| ScriptAgent | `script` | `script:<command>` | 确定性命令执行一次 |
| BatchAgent | `batch` | `batch:cmd=<tmpl>&glob=<p>&concurrency=<n>` | glob 展开同构并行 |
| WatchAgent | `watch` | `watch:path=<dir>&cmd=<tmpl>&polls=<n>&interval=<ms>` | 有界轮询监控文件变化并触发 |

实现文件：`mode_agent_common.{h,cpp}`（spec 解析/`{item}` 物化/glob 展开/快照签名/
白名单执行）、`script_agent`/`batch_agent`/`watch_agent`、`agent_loop_adapters`
（Script/Batch/Watch 适配器）、`query_engine::make_loop` 三分支。

安全：命令模板的「真实执行的 token」经 `guard_command` 白名单；`{item}` 物化时对
shell 敏感字符做拒绝（防注入）。Batch 用 `std::thread` 有界并发执行（`process::exec`
线程安全）。Watch 用「大小+mtime」快照签名做变化检测，轮询次数有界不在单 turn 挂起。

**明确不做**：Scheduled（cron 触发，留待外部 TaskManager 调度）与 BlockingScript、
Cron 工具，避免范围失控。
