## 3. 实施计划

### 阶段 A：内置工具补齐（P0 → P1 → P2）

**A1. #25 WebFetchTool 真实化（P0）**
- 引入 HTTP 客户端（优先 cpp-httplib 或 Boost.Beast，需评估现有依赖）
- `WebFetchTool::call()` 实现：GET url → 提取 HTML 正文 → 可选按 prompt 摘要
- 注册到 `register_builtin_tools()`，补充单元测试（mock HTTP 层）

**A2. #25 WebSearchTool 新增（P0）**
- 新增 `src/agent/tool/WebSearchTool/web_search_tool.{h,cpp}`
- 接入搜索 API（需确认可用后端，如 DuckDuckGo HTML 接口 / Tavily / 自建）
- 注册 + 单元测试

**A3. #27 MCPTool 真实化（P1）**
- 实现 MCP JSON-RPC 客户端（stdio 或 HTTP transport）
- `call()` 调用 MCP server 的 `tools/call`
- 新增 `MCPResourceList` / `MCPResourceRead` 工具（List/Read MCP Resource）
- 注册 + 单元测试（mock MCP server）

**A4. #29 NotebookEditTool 新增（P2）**
- 新增 `src/agent/tool/NotebookEditTool/notebook_edit_tool.{h,cpp}`
- 解析 .ipynb JSON，支持 cell 增删改
- 注册 + 单元测试

### 阶段 B：TUI 功能补齐（P0 → P1 → P2/P3）

**B1. #62 输入框多行编辑（P0）**
- composer 从单行 Input 升级为多行自绘编辑器（`Renderer` + `Canvas` 或 `Paragraph`）
- Enter 提交 / Shift+Enter 换行；输入框高度随内容增长
- 保留粘贴多行处理（改为真实换行而非转空格）

**B2. #63 输入历史持久化（P1）**
- 新增历史存储（JSON 文件，如 `~/.config/workx/history.json`）
- 上下箭头浏览历史，去重、上限（如 200 条）
- 启动时加载、提交时保存

**B3. #66 首次运行设置向导（P2）**
- 首次运行检测（配置文件不存在时）
- FTXUI 向导界面：Provider 选择、API Key 输入、上下文长度设置
- 完成后写入配置文件

**B4. #64 Tree-sitter 语法高亮（P2）**
- 引入 tree-sitter 依赖（CMake 选项 `WORKX_WITH_TREE_SITTER` 已存在）
- 替换 `syntax_highlight.cpp` 的关键字分词为 tree-sitter 解析
- 支持语言：C/C++、Python、JS/TS、Rust、Go、Bash、SQL、JSON

**B5. #65 细粒度 Token 统计（P3）** ✅ 已实现
- ActionTurnDone 新增 prompt_cache_hit_tokens / prompt_cache_miss_tokens（事件桥接透传 StreamDoneEvent）
- SidebarModel 新增 prompt_tokens / generated_tokens / cache_hit_tokens / cache_miss_tokens（会话累计）
- 侧边栏新增两行：`DS 缓存 命中 80% (8k/10k)` + `Prompt 10k · 生成 2k`（无数据时隐藏）
- total_tokens / cache_read_tokens 改为累计，保留 resume 后历史

## 4. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| WebSearch 需外部 API | 依赖第三方服务 | 优先 DuckDuckGo HTML 免 key 方案，可替换 |
| Tree-sitter 引入外部依赖 | 构建体积/复杂度增加 | 用 CMake 选项控制，可选编译 |
| MCP 协议实现复杂 | 工作量最大 | 先支持 stdio transport + tools/call 最小闭环 |
| 多行输入自绘 | FTXUI 组件复杂度高 | 参考现有 suggest_panel 自绘经验 |
